Security

How OpenSAM is secured, how to report a vulnerability, and what happens after you report.

Effective date: September 16, 2026 · Last updated: September 16, 2026 · Operator: AliceLabs LLC · Jurisdiction: United States

This page describes how OpenSAM, operated by AliceLabs LLC, approaches security. It covers our practices, the responsible disclosure process for security researchers, and our compliance roadmap.

1. Security practices

Encryption

  • In transit: TLS 1.3 for all HTTP traffic. HSTS enforced on opensam.us and all subdomains.
  • At rest: AES-256 for all stored data, including database, object storage, and backups.
  • Key management: AWS KMS with customer-managed keys for Enterprise customers.

Access controls

  • Role-based access control (RBAC) with least-privilege defaults.
  • Multi-factor authentication (MFA) required for all administrative access.
  • Access reviews performed quarterly; access revoked within 24 hours of personnel changes.
  • Just-in-time access for production systems via approved break-glass procedures.

Network security

  • VPC isolation for production workloads.
  • No public inbound access to databases or internal services.
  • Web Application Firewall (WAF) on all public endpoints.
  • DDoS protection via AWS Shield Standard.

Vulnerability management

  • Continuous dependency scanning via Dependabot and Snyk.
  • Static analysis on every commit (CodeQL via GitHub Actions).
  • Annual third-party penetration testing; reports available to Enterprise customers under NDA.
  • Responsible disclosure program (see Section 2 below).

Audit logging

  • All access to production systems and customer data is logged.
  • Logs retained for 24 months.
  • Enterprise customers can subscribe to audit log export via webhook or S3.

Incident response

  • Documented incident response plan with defined roles, severity levels, and communication protocols.
  • 24-hour notification to affected customers for confirmed security incidents.
  • Post-incident review within 14 days; root cause and remediation shared with affected customers.

2. Responsible disclosure

If you believe you have found a security vulnerability in OpenSAM, please report it responsibly:

  • Do not open a public GitHub issue.
  • Email contacto@alicelabs.site with subject “Security vulnerability.”
  • Include: a description of the vulnerability, the steps to reproduce, and the potential impact.
  • If possible, suggest a fix.

We will acknowledge receipt within 72 hours and aim to issue a fix within 30 days for high-severity issues. We will credit you in our security advisories unless you prefer to remain anonymous.

Safe harbor: We will not pursue legal action against researchers who make a good-faith effort to disclose vulnerabilities in accordance with this policy, provided they do not access, modify, or delete data that does not belong to them.

4. Data residency

Pro plan data is stored in AWS us-east-1 (Northern Virginia, United States). Enterprise customers can choose from any AWS region, including AWS GovCloud (US) for federal workloads. Backups are encrypted and stored in a different availability zone from the primary data.

5. Third-party security

We rely on the following third-party services, all of which have their own security programs:

  • Amazon Web Services — hosting, computing, storage. AWS Security.
  • Stripe — payment processing. Stripe Security. PCI DSS Level 1.
  • GitHub — source code hosting. GitHub Security. SOC 2 Type II.

6. Bug bounty

We do not currently run a paid bug bounty program. Researchers who report valid high-severity vulnerabilities may receive OpenSAM Pro credits or be publicly acknowledged at their preference. We are evaluating a paid bounty program for 2027.

7. Security advisories

Security advisories are published on our GitHub Security Advisories page: github.com/eddyflores100-lang/OpenSAM/security/advisories. Pro and Enterprise subscribers receive email notifications for any advisory affecting their version.
